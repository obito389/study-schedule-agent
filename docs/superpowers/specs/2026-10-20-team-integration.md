# 团队模块集成设计

用户已授权：先保留完整版，再直接修改现有模块、参考完整版补齐完整链路。

## 方案
以 main 已评审的契约、排程、Agent、用户模型和赵欢的 ImportService 为基础，合入完整版中已经测试的持久化适配器、DeepSeek 适配器与前端。移植黄健华执行器的两阶段、原子批次、版本/幂等/审计/撤销要求到同一 ActionExecutor，避免部署两个 Spring 应用或混用两套 Flyway 迁移。保留原提交和原 PR，清楚记录采用与未采用的部分。复用樊华钰的状态与冲突反馈组件，连接真实 API。

## 数据流
前端输入 → Agent/导入候选 → 明确预览与确认 → 单一 ActionExecutor → 统一硬约束和用户版本锁 → 数据库 → 日程刷新 → 完成任务耗时反馈。模型调用不持有数据库事务。

## 验收范围
- 任务、规则排程、AI 草案、导入确认、课程、固定时段、偏好写入与审计接通；保存后刷新/重启仍存在。
- 批次预览不落库；批次任一动作不合法时整体不写；成功只推进一个版本；相同请求原样重试不重复写入；撤销不得覆盖后续修改或制造冲突。
- DeepSeek 文本导入使用真实适配器；截图和音频若没有识别服务必须标明手动校对，不伪装识别成功。
- H2 自动测试 + 独立 MySQL 8 库验证迁移、原子性、并发和重启；浏览器端到端验证。
- 原完整版分支、未提交文件、8080/5174 服务及其数据库保持不变，新服务使用独立端口和库。

## 不混入的实现
backend-hjh 的 Long ID/LocalDateTime/16 表迁移与主线契约不兼容，不直接复制扫描加载；采用其业务要求，在主线契约下实现。额外表 CRUD 和任务步骤不假称已接入当前前端。当前产品仍是单用户本机学习工作台。
